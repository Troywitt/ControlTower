# Security boundary — review version 0.2

## Dashboard

The active executable is `ControlTowerLocal`. It is ad-hoc signed with hardened runtime and App Sandbox, and only `files.user-selected.read-only`. **No network-client entitlement**, updater, shell/process launch, credential entry, Keychain adapter, browser-cookie or provider-auth-file discovery. The old direct-token core is isolated in a test-only target and is not a product dependency. `KeychainVault.swift` is explicitly excluded from the executable.

Users select a dedicated quota-feed folder, granting the dashboard read access to that folder for this launch. It reads fixed `claude.json`/`codex.json` names every five seconds while enabled. Disconnect ends reads and the security scope. No persistent bookmarks or startup reconnection. Folder-level grant is necessary because atomic replacement changes file identity; select only the dedicated quota folder, never a credential/state/project folder. Files must be regular, non-symlink, bounded; feed JSON has a strict field/provider/window allowlist and rejects booleans, nonfinite values, invalid percentages, future timestamps and unknown fields. Missing/error data removes displayed success; observations older than five minutes are marked stale. Local same-user tampering cannot be prevented by this JSON boundary; feeds are not cryptographically authenticated. StatusLine observation time is not a guaranteed network-fetch time.

## Claude bridge

`Bridges/prepare_claude.py` generates review/rollback patches; it never edits `.claude/`. It reads the user-selected settings file locally but only retains statusLine. Existing command/options are preserved; unknown formats, recursive wrapping and overwrite attempts fail. Review directory must be private. The statusLine bridge receives official stdin, bounds it, selects only quota percentages/reset times, and publishes using a 0600 temporary file + atomic rename. It never saves/logs raw stdin or transcript/path/session fields. If an existing command is preserved, raw input is passed **in memory** to that same trusted command, as Claude already did; its preexisting privileges/behavior are not sandboxed or audited by this fork. Prior command output goes directly to the terminal, stderr is suppressed, and a timeout bounds waiting. No provider credentials are used by the bridge.

## Codex adapter

`Bridges/codex_quota.py` is **user-started outside the app sandbox** in a private terminal. It verifies the explicit executable's SHA-256 and Apple signing requirement (identifier `codex`, team `2DC432GLL2`) before starting the unmodified provider executable. It uses a dedicated private home and empty working directory with a fresh allowlisted environment, excluding inherited provider keys, proxies and endpoints. First-use state must be empty; a marker guards accidental selection of an unrelated state folder. CODEX_HOME and credential storage are configured for the child only; existing user config is not modified or inspected. System/MDM policy still applies.

Stdio has fixed RPCs: initialize, device-login start/cancel, quota read. No general RPC/UI command surface; no turns, tools, model prompts, credits/reset, email or generic account operations. Incoming server requests fail closed. Device destination is fixed to `https://auth.openai.com/codex/device`; code stays in the user's terminal and is never published. OAuth/session tokens and credential files are never requested/read by wrapper or dashboard. Official Codex owns its authentication, Keychain storage and refresh. Explicit `keyring` requests no plaintext fallback; real behavior and rebuild/persistence must still be live-tested. The official binary may possess account access broader than quota reads; our method allowlist is not OS isolation of that binary.

The helper writes only normalized quota fields, uses bounded framed input/timeouts, never logs provider bodies or errors, suppresses child stderr, and terminates its process group on exit. Refresh is user-owned; failure exits without fallback/retry. The device flow needs no wrapper network listener or app entitlement expansion. The child still has normal user-process network access: **old URLSession host restrictions do not apply to it**. Disconnecting the dashboard does not kill this separate helper; quit it in Terminal. Saved provider login remains provider-managed. No global certificate/network/security setting is changed.

## Gemini and residual limits

Gemini is unavailable until a defensible quota-only integration exists. Interactive CLI quota support is not equivalent to a stable headless API. No headless `/stats` invocation, OAuth client-key copying, token extraction, auto-trust or internal API request is shipped.

Ad-hoc signing is not notarization or identity continuity. A compromised user account, app, helper, official provider binary or OS can defeat these boundaries. Signature/hash checks reduce substitution risk but do not make same-user filesystem changes impossible. No absolute security or provider-terms guarantee is claimed. Synthetic tests verify our boundaries, not provider reliability or real account authentication. See [PROVIDER-SETUP.md](docs/PROVIDER-SETUP.md) and [HANDOFF.md](docs/HANDOFF.md) for acceptance gaps.
